# Skill: Note Merge — 调研笔记合并

## 能力
当用户要求记录/总结/整理科研笔记时，自动检查 `kb/` 目录下是否有**内容相似**的已有笔记，有则合并或追加，避免碎片化。

## 触发场景
用户表达以下意图时自动激活：
- "帮我总结一下 X 方法"
- "记一下 X 论文的要点"
- "整理一下 X 这条线的进展"
- "X 和 Y 什么关系，帮我记下来"

## 步骤

### 第一步：查重
用 `glob("**/kb/*.md")` 列出所有已有笔记，逐篇检查内容是否与新笔记相关：

**检查维度：**
1. **方法名匹配**：新笔记涉及的方法（如 "Soft Teacher"）是否在已有笔记标题或内容中出现
2. **技术线匹配**：新笔记是否属于已有笔记的同一条技术演进线（例如都在讲半监督检测）
3. **关键词重叠**：数据集（DOTA/HRSC2016）、概念（consistency regularization/uncertainty sampling）是否高度重叠

### 第二步：决策（三种路径）

| 情况 | 操作 | 原因 |
|------|------|------|
| **高度重叠**（同一方法/同一条线的新进展） | 用 `edit_file` 追加新内容到已有笔记，更新目录/索引 | 一篇笔记维护一条技术线 |
| **部分相关**（新方法属于已有笔记的旁支或对比对象） | 追加到已有笔记的"相关方法"或"对比"章节 | 便于横向对比 |
| **完全不重叠** | 新建文件 `kb/新笔记名.md` | 开辟新线 |

### 第三步：追加/合并时的规范

追加到已有笔记时，保持原有结构：

```
# 原标题
... 原有内容 ...

## 2026-07-05 追加：新方法/新进展
- **方法：** [方法名]
- **论文：** [标题] ([年份])
- **核心思想：** ...
- **关键数字：** DOTA mAP=xx.x
- **与已有方法的关系：** 基于 X 改进 / 对比 Y 高 x 个点
```

- 每次追加标注日期，形成时间线
- 新内容写在末尾，不破坏已有内容的章节结构
- 如果新内容足够多（>5 个方法），建议在文件头部更新目录

### 第四步：交叉验证
追加完成后，如果笔记中包含数字指标，用 `search_papers` 或 `query_graph` 做一次交叉验证，确保追加的数字准确无误。

## 工具
- `glob(pattern)` — 搜索 kb/ 目录下的调研笔记文件
- `read_file(path)` — 读取已有笔记全文
- `edit_file(path, old_string, new_string)` — 在已有笔记末尾追加新内容
- `write_file(path, content)` — 创建全新笔记
- `search_papers(query, top_k)` — 验证数字指标

## 使用示例
- "帮我总结一下 Focal Teacher 这篇论文" → 检测到 `kb/soft_teacher_survey.md` 已有相关技术线，追加到对应章节
- "记一下最近看的 Semi-DETR++" → 检测到已有 Semi-DETR 的笔记，追加新版本信息
- "整理一下主动学习在遥感检测上的最新进展" → 新建 `kb/al-remote-sensing-survey.md`

## 注意事项
- **追加比新建好**：同一技术线尽量放在一篇笔记里，方便用户一口看完脉络
- **不要过度合并**：如果只有部分关键词重叠（比如都用 DOTA 但方法方向不同），应分开笔记
- **不能确定的问用户**：如果查重后不确定是该合并还是新建，直接问用户
